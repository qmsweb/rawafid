# AGENTS.md

## What this is

Jekyll static site (no Gemfile, no package.json, no plugins) for "روافد", an Arabic RTL educational platform (`rawafid.jassim.one`, CNAME → GitHub Pages). Run `jekyll serve` / `jekyll build` directly (install Jekyll via `gem install jekyll` if missing). No test/lint/typecheck tooling exists.

**`_site/` build output is committed to git** (1093 tracked files). Commit it after a build. `.jekyll-cache` is not tracked; there is no `.gitignore`.

## Codegen: always regenerate after editing data

Data lives in `assets/`; PowerShell generators (run with `pwsh` from repo root) turn it into Jekyll pages. Each script **wipes its output directory before regenerating** — don't hand-edit generated files, they will be deleted.

| Edit this | Run this | Output | CI? |
|---|---|---|---|
| `assets/data/*.json` | `./generate-details.ps1` | `details/<CODE>/<ID>.md` | yes (push to `assets/data/**`) |
| `assets/calendar.json` | `./generate-events.ps1` | `_events/<date>.md` (slug = date) | yes (push to `assets/calendar.json`) |
| `assets/plans/edu.json`, `aadab.json` | `./generate-plan-courses.ps1` | `assets/plans/<plan>/<CODE>.json` + `tools/study-plan/<plan>/<CODE>/index.md` | yes (push to those two files) |
| `assets/online/*.yaml` | `./generate-exams.ps1` | `exam/<CODE>/index.md` + `exam/<CODE>/print/index.md` | **no workflow — run manually** |

- CI (`.github/workflows/`, windows-latest) auto-commits regenerated pages with `[skip ci]` and pushes back. Don't commit the same generated output by hand for the CI-covered generators — just push the data change.
- `generate-details.ps1` **skips** `materials.json`, `one.json`, `test.json` in `assets/data/` (helper/test fixtures).
- `generate-plan-courses.ps1` plan list is hardcoded (`edu`, `aadab`) — adding a plan means editing the script.
- Scripts write UTF-8 **without BOM** and keep Arabic characters unescaped (PS 5.1-compatible `ConvertTo-CleanJson`); preserve that when editing them.

## Runtime behavior

- Layouts fetch data **client-side at runtime**: `details.html` fetches `assets/data/<CODE>.json?timestamp` with `cache: no-store`; study-plan pages fetch per-course JSON; exam pages parse `assets/online/*.yaml` in the browser via js-yaml CDN. Data files are runtime inputs, not just build inputs.
- `blog-index.json` is Liquid-generated by Jekyll (consumed by `search.html`).
- Theme: `data-theme` attribute on `<html>`, persisted in localStorage key `rawafed-theme`, managed by `assets/js/theme.js`.
- `sw.js` caches fonts only — bump `FONT_CACHE` version (`rawafid-fonts-v1`) when fonts change.

## Conventions

- `_config.yml`: `permalink: /blog/:slug`, events collection at `/events/:name/`, `timezone: Asia/Muscat`, `future: true` (calendar events are future-dated and must always publish).
- `_data/tools.yml` is the **single source** for the tools list — edit only that file, not the pages that render it.
- Root `calendar.html` is just a redirect to `/tools/calendar`. Root pages (`index.html`, `about.html`, `tools.html`, …) are Liquid stubs with front matter pointing to layouts in `_layouts/`.
- Shared styling: `assets/css/design-system.css` (tokens like `--rawafid-primary`, `--rawafid-bg`, `--radius-md`) + `assets/js/theme.js` + fonts from `fonts/`.

## Design rules (from `.opencode/.agents/rwfd-desinger.md`)

- Never hardcode hex colors in elements — use the CSS variables. Site supports dark/light modes.
- Don't modify global styles; add page-specific classes instead.
- Font stack is IBM Plex Sans Arabic / Thmanyah — don't change `font-family`.
- That agent file also requires explaining the plan and getting approval **before** editing `index.html`.

## Gotchas

- Some older layouts (`details.html`, `exam.html`, …) still define their own local `:root` variables instead of using `design-system.css` — mixed state; check which system a page uses before restyling.
- Exam layout deliberately blocks zoom/double-tap/ctrl-scroll (mobile kiosk behavior) — don't "fix" it.
- Empty file `main` at repo root is a leftover; ignore it.
- Git history messages are terse ("V3") — no commit-message convention to follow.
